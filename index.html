01 — About

Engineering as a tool for consequence.

My approach comes down to one habit: understand the first principles, learn relentlessly, and execute under pressure. I would rather write the solver than import it — not out of stubbornness, but because you cannot debug what you never understood.

My work sits in two disciplines that keep sharpening each other: software development and AI/ML. On the modelling side, built from the ground up — classical regression, ensemble methods, dimensionality reduction, deep neural networks. On the engineering side, everything that turns a model into software someone can use: ETL pipelines, APIs, application state, deployment — down to C++ memory models, cache behaviour, and parser design when the problem asks for it.

Technology is only as valuable as the problems it solves. My flagship research builds a predictive early-warning model for Japanese Encephalitis in Assam. That work is personal. For me, engineering is not an academic pursuit — it is a way to create tangible, life-saving impact.

LinkedIn ↗ GitHub ↗

Build the primitive first

Gaussian elimination with partial pivoting, hand-rolled. A recursive-descent parser instead of a grammar generator. The abstraction only earns trust once you have built what sits underneath it.

Validate like a skeptic

Strict time-series splits, no shuffled folds, no peeking at the future. A backtest that flatters you is worse than no backtest at all — it is a confident lie.

Domain over model

Mass-balance hydrology and thermal vector-growth constraints beat a bigger network. Encoding how the world actually works is the highest-leverage feature engineering there is.

Ship under a clock

Competitive programming taught me to decompose a problem, pick the data structure, and commit — with the timer running. That instinct carries straight into production work.

JEV Bio-Hydrological Predictive Radar

Japanese Encephalitis early-warning system · Assam

A predictive and prescriptive vector-control platform. It ingests satellite and weather data onto an H3 hexagonal grid, derives standing-water availability through a mass-balance hydrology model, constrains mosquito population growth with thermal degree-day limits, and applies cohort time-lags so risk surfaces appear weeks before cases do.

  • Migrated from a naïve raster grid to H3 indexing for uniform-area neighbourhood queries
  • Mass-balance water budget: rainfall in, evapotranspiration and infiltration out, breeding habitat as the residual
  • Thermal growth ceilings stop the model predicting outbreaks the vector biologically cannot support
  • Five validated build phases, each with its own notebook and hold-out check

    NL-to-SQL Service & Eval Harness

    Python · FastAPI

    Hardened natural-language SQL service

    A FastAPI service that turns questions into SQL and refuses to run anything unsafe: an sqlglot AST gate blocks DML/DDL, stacked queries, unsafe functions and unbounded CROSS JOINs, EXPLAIN (FORMAT JSON) checks cost and scans, and a SELECT-only Postgres role enforces a 3s statement_timeout. BM25 plus 1-hop FK schema linking, DSN-keyed pooling, per-request JSON telemetry, and bounded retries — max 2 on fixable errors, an immediate HTTP 403 with 0 retries on security violations. Evaluated on a deterministic 7-table, 50,000-row benchmark with a 60-query execution-accuracy harness (CTEs, window functions, adversarial SQLi).

    • PostgreSQL 16
    • sqlglot
    • Docker
    • pytest
    • 47/47 security tests

  • Write path · durability

    Redis-Lite

    C++20

    Crash-safe RESP2 key-value server

    A single-threaded, non-blocking poll(2) RESP2 server with pipelining and redis-cli compatibility — 97,847 SET/s and 101,317 GET/s (294,637 SET/s pipelined, 50 clients). A CRC32-framed binary WAL with group commit holds replies until one shared F_FULLFSYNC covers the batch: durable writes up 6.5x (513 to 3,347 SET/s), 26.4x pipelined. Crash-tested across 20 SIGKILLs with 0 of 6,644 acknowledged writes lost; torn tails truncate, mid-file corruption is rejected, compaction is atomic (53.0 MB to 5.3 MB), and 44 C++ tests pass under ASan/UBSan with -Werror.

    • poll(2)
    • Binary WAL
    • Group commit
    • Docker
    • ASan/UBSan

    btreedb

    C++17

    Disk-backed database engine

    A single-file database, built layer by layer: a pager over raw pread/pwrite, an LRU buffer pool with pin counts and dirty flags, slotted heap pages, a B+ tree with linked leaves, then a recursive-descent SQL parser and planner on top. The point is the instrumentation — every query reports the plan it chose and what it cost in pages read.

    jit

    C++17

    x86-64 JIT compiler

    Compiles arithmetic expressions straight to machine code at runtime — lexer, parser, then SSE2 instructions encoded byte by byte into a W^X mmap'd buffer and called as a function pointer. A tree-walking interpreter acts as the oracle, and 100,000 differential fuzz cases check the two agree. Every emitted instruction has a golden-byte test.

    Auto Diff Engine

    Python

    Reverse-mode autodiff, stdlib only

    Backpropagation with nothing underneath it — no NumPy, no PyTorch. It builds the expression graph as you compute, topologically sorts it, and replays it backwards to exact gradients. Then it trains an MLP on two-moons to prove those gradients are good enough to actually learn with, and checks every one against central differences.

    • Backprop

    • 53 tests
    Local build · publishing soon

    DNS Resolver

    C++17

    Iterative resolver from scratch

    It starts at the root servers and walks the delegation chain down to the authoritative nameserver itself — it never asks a public recursive resolver anything. POSIX sockets only; the wire format is encoded and decoded by hand against RFC 1035. --trace prints every hop with packet hexdumps, laid out to read side by side with dig +trace.

    • RFC 1035
    • UDP sockets
    • TTL cache
    Local build · publishing soon

  • Round-robin trace

    Mini-OS

    C++20

    Simulated operating system

    A kernel that owns a scheduler, a memory manager, a process table, and a resource manager, running processes through their full lifecycle — preemption, register save and restore, page faults, syscalls, blocking and waking. Swapping Round Robin for FCFS changes one unique_ptr and nothing else. It also reproduces a real race condition, then catches a deadlock by finding the cycle in its own wait-for graph.

    • Scheduling
    • Virtual memory
    • Deadlock detection
    • RAII ownership
    Local build · publishing soon

04 — Journey

Every project on this page traces back to the same question: what is actually happening one layer below the abstraction I was handed?

Building reproducible Docker environments, gold reference patches, and pytest verification suites (live database/service checks and static analysis) calibrated with fail-to-pass quality gates.

  2. Oct 2026 – Present · Remote · Contract

    Technical Reviewer (promoted from Contributor) · Mercor

    Auditing engineering workflow trajectories for code correctness, SQL/Python verification rigor, source provenance, and specification adherence across frontier LLM post-training datasets. Authoring automated Python and SQL validation scripts that check boundary conditions, data integrity, and execution reproducibility across multi-step technical tasks.

  3. Jun 2026 – Jul 2026 · Silchar, India

    Research Intern, Human-Robot Interaction with AI · NIT Silchar (SN Bose Summer Internship Program)

    Built an LLM prompting and structured-output layer that converts natural-language directives into strict, schema-validated robot task specs, rejecting malformed or unsafe actions before actuation. Developed a real-time perception and closed-loop control pipeline on Raspberry Pi, YOLOv8n, and ESP32 (640x480 at 15 FPS, 15 PID commands/s) with tracker fallback, target re-acquisition, watchdog timeouts, and sensor-loss fail-safes.

  4. Also now

    Raft, from the paper up

    Building raftlite: consensus over a deterministic network simulator, with a history checker that replays each run to prove linearizability held. Alongside it, the JEV model is in Phase 5 — validated against held-out seasons rather than one aggregate score.

  5. 2026

    Removing the magic, one layer at a time

    A run of systems projects, each one deleting a dependency I had been taking on faith. A database down to the page. A JIT down to the instruction bytes. A resolver down to the DNS wire format. Backpropagation and a transformer with no framework doing the derivative for me. The pattern is always the same: build the thing you were importing.

  6. 2026

    Down to the metal with C++

    Built MatVM to answer a question ML libraries hide: what actually happens when you solve a linear system? Flat buffers, pivoting, a hand-written parser — and a decision log kept for every trade-off I made and rejected.

  7. 2026

    Shipping ML to real users

    AlgoMentor AI and the ML Trading Predictor both went live. Two very different domains, one shared lesson: the deployment surface changes what you are willing to claim about a model.

  8. 2025

    Contests, and the habit they build

    Regular Codeforces rounds alongside coursework. Rating comes and goes; what stuck was the reflex — read the constraints first, pick the structure, commit. Every project after this one was decomposed the same way.

  9. Aug 2023 – May 2027 · CGPA 7.26/10.0
